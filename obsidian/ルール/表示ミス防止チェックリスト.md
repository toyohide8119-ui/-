# 表示ミス防止チェックリスト

画面（HTML/CSS）を作る・直すたびに、**ユーザーに「直しました」と伝える前に**全部確認する。
根拠になったミスは、各項目の右にリンクで書いてある。

## 1. データ：本物に近いデータで確かめる
- [ ] テスト用の短いデータだけで判断しない。**実際のデータ（いちばん長い品名・相手先・人の名前）**でも表示を確かめる → [[M05 短いテストデータで確認して実データで崩れた]]
- [ ] 長い文字は「折り返す」か「…で省略」かを項目ごとに決める。**区別に必要な部分（例：13㎜・白黒・会社名）は省略しない**
- [ ] 本物のデータを使うときは**読むだけ**にして、勝手に書き込まない
- [ ] 数字の欄は**いちばん桁の多い数（4桁・5桁）**の品目が写った状態で見る → [[M15 在庫の数字が4桁なのに3桁しか見えなかった]]

## 2. 画面の幅：スマホの幅で全部測る
- [ ] 幅 **360 / 375 / 390 / 430** px で確認する（いちばん狭い 360 を必ず含める）
- [ ] 横にはみ出していないか数字で測る（`scrollWidth` と `clientWidth` が同じか）
- [ ] 表の行の高さがそろっているか測る（行ごとの高さを出して比べる）→ [[M08 品目ごとの増減の品名が2段になった]]
- [ ] ダークモードでも確認する

## 3. 表（table）
- [ ] 全体用の `th:first-child { min-width }` のような指定が、ほかの表に効いて列を細くしていないか確かめる → [[M01 今日の動きの品目が4行に折り返した]]
- [ ] 1行にしたい列は `white-space: nowrap` を**中のボタンやリンクにも**付ける（iPhone の Safari はボタンだけ折り返すことがある）→ [[M08 品目ごとの増減の品名が2段になった]]
- [ ] 単位が全部同じなら、数字の横ではなく見出しにまとめて幅を節約する

## 4. iPhone 特有
- [ ] 入力欄（input / select / textarea）の文字は**スマホでは 16px 以上**（16px 未満だと触った瞬間に画面が拡大して飛ぶ）→ [[M06 入力中に画面が下に飛んだ]]
- [ ] `scrollIntoView` は画面全体まで動かす。一覧の中だけ動かしたいときは、その箱の `scrollTop` を直接変える → [[M06 入力中に画面が下に飛んだ]]
- [ ] キーボードが出ると見える高さが減る。候補の一覧などは `visualViewport` で高さを合わせる
- [ ] ここ（クラウド）には iPhone と同じ表示エンジン（WebKit）がない。**Chromium で問題なくても iPhone で崩れることがある**前提で、余裕を持たせる

## 5. 隠す・重ねる
- [ ] `[hidden] { display: none !important; }` を必ず入れる（`display:flex` などを付けた要素は hidden が効かなくなる）→ [[M02 隠したはずの欄が見えていた]]
- [ ] 画面上部に固定（sticky）の部分があるときは、スクロール先が隠れないように `scroll-margin-top` を付ける → [[M09 並べ替えの説明が固定ボタンの裏に隠れた]]
- [ ] 入力欄の幅を変えたら、日付入力が欠けていないか確認する → [[M10 日付の欄が欠けた]]
- [ ] 要素の種類を変えたら（input → button など）、`.親 button { width }` のような**まわりの指定がぶつかっていないか**、実際の幅（offsetWidth）を測る → [[M15 在庫の数字が4桁なのに3桁しか見えなかった]]

## 6. 状態の切り替え
- [ ] 種類を切り替える処理（出庫予約⇄製造予定など）で、説明文や見出しが古い文言で上書きされていないか確認する → [[M11 切り替えで説明文が古いまま]]
- [ ] 絞り込みの結果が「0件」にならないか、入力と完全一致したときの動きも試す → [[M07 候補が空になった]]

## 7. 見た目の確認
- [ ] スクリーンショットを撮って**自分の目で**見る（数字だけで判断しない）
- [ ] ユーザーから「直ってない」と言われたら、まず [[公開と確認の手順]] の「古い画面のまま」を疑う
