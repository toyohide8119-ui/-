# 公開と確認の手順

## 「直しました」と伝える前に
1. [[表示ミス防止チェックリスト]] を全部確認した
2. 公開（GitHub Actions の Pages）が**成功したのを自分で確認した** → [[M12 公開を確認する前に公開済みと伝えた]]
3. バージョン（画面右下の Ver.）を上げた
   - Firebase のルールの貼り替えが必要 → 整数を上げる（Ver.26 → Ver.27）
   - それ以外 → 小数点以下を上げる（Ver.26 → Ver.26.1）
   - `app/sw.js` のキャッシュ名も必ず変える（変えないと古い画面が残る）
4. ユーザーへの返事に**新しい Ver. の番号**を書く
5. ルールの貼り替えが必要なときは、**貼り付け用のルール全文**を毎回渡す

## 「直ってない」と言われたら
1. まず画面右下の **Ver. の番号**を聞く → [[M04 古い画面のままで直っていないと言われた]]
2. 番号が古い → アプリを完全に閉じて開き直してもらう
3. 番号が新しいのに直っていない → スクリーンショットをもらい、どの表・どの部分かを確かめる（推測で直さない）
4. 何を直せばよいか迷ったら、**必ずユーザーに質問する**

## 公開の失敗
- GitHub Pages の公開は、作成（build）と公開（deploy）を別の job に分けておく（1つの job だと「github-pages が見つからない」で時々失敗する）→ [[M13 公開が一時的なエラーで何度も失敗した]]

## ファイルを渡すとき
- 日本語の名前が入った ZIP は、`zip` コマンドではなく Python の `zipfile` で作る（UTF-8 の印が付く）→ [[M14 渡したZIPのファイル名が文字化けした]]
- 渡す前に自分で展開して、名前と中身が正しく読めるか確かめる
